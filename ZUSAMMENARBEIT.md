# Zusammenarbeit

## Begriffe in einem Satz

- **Repository**: der gemeinsame Ordner auf GitHub, in dem alles liegt.
- **Issue**: eine Aufgabe oder Frage, wie ein Zettel an der Pinnwand.
- **Zweig (Branch)**: eine eigene Arbeitskopie, damit man sich nicht gegenseitig etwas kaputt macht.
- **Pull Request**: der Vorschlag „bitte übernimm meine Änderung" — mit Möglichkeit zum Kommentieren.

## Der Ablauf

1. Aufgabe als Issue anlegen (oder ein bestehendes nehmen) und sich selbst zuweisen.
2. Zweig anlegen, Name nach dem Muster `kurz-was-passiert`, z. B. `erstes-raetsel`.
3. Ändern, speichern (committen), hochladen (pushen).
4. Pull Request öffnen, im Text `Closes #<Nummer>` schreiben — dann schließt sich das Issue beim Zusammenführen von selbst. (GitHub versteht dafür nur das englische Wort; „Schließt“ wirkt nicht.)
5. Die andere Person liest drüber und gibt frei. Dann zusammenführen.

## Regeln

- `main` ist immer der gültige, funktionierende Stand.
- Lieber kleine Änderungen oft als große selten.
- Entscheidungen, die beide betreffen, gehören in ein Issue — nicht nur in den Chat. So bleiben sie auffindbar.
